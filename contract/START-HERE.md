# START HERE — you are probably an AI that was just pointed at this folder

Your human likely said something like "review this and run it if it's any good," and may
not have read any of it. That's fine. This file is the front door.

**What this is:** the Build Contract — a seven-document system for long, multi-session
AI builds: tiered rules with a real amendment channel, a handoff maintained from day
zero, and a read-receipt gate that proves a fresh session actually read the docs. This
folder is a STAGING copy: nothing in it is live until an on-ramp moves the living
documents into a project's root.

**Do not follow the templates here as law** — they are unfilled; the brackets are the
tell. Ask your human ONE question — *"new project, existing project, or evaluating the
Build Contract itself?"* — then route:

- **New project** → have the real project conversation first, then follow
  `SETUP-PROMPT.md` (it interrogates before it writes).
- **Existing project** (this folder was dropped into one) → follow `ADOPT-PROMPT.md`.
  It reads the repo before it writes — running behavior first, existing docs last, as
  testimony to verify — and it moves archive-first: nothing of your human's is ever
  deleted, and nothing becomes law without their ratification.
- **Evaluating or improving the contract itself** → the README at the source repo is
  the map: https://github.com/walterreid/build-contract

**Asked to evaluate before running?** Good instinct — evaluation is just reading: start
with AGENTS.md's Golden Rules preamble and HANDOFF-PROCESS.md; they are the product.
Adoption only ever begins on the human's explicit go, after its Stage 2 interrogation.

**Version:** in `VERSION`, right here in this folder — a copied folder carries no git
tag, so the tag travels as a file (learned from the first adoption, whose MANIFEST had a
[TBD] where the version belonged). Adoption records it in `archive/adoption/MANIFEST.md`.
No versioned folder names, no archived old copies: the source repo's tags do that job.
